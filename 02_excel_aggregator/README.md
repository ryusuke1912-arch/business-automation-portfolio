# 書式バラバラのExcelを一括集計するツール

フォルダに溜まった見積書Excelを全部読み取り、一覧表・取引先別集計・月別集計に変換します。

> 入力サンプルの社名・担当者名・金額はすべて架空です。

---

## この手の自動化が現場で壊れる理由

「Excelを集計する」依頼で一番多い失敗は、**セル位置の決め打ち**です。

```python
見積番号 = ws['B3'].value      # ← これが破綻の原因
```

取引先ごと、年度ごと、担当者ごとにフォーマットは必ずズレます。
1つでも列が挿入されれば、そのツールはその日から嘘の数字を出し続けます。

## 対策：ラベルを探して、その隣を読む

本ツールはシート全体を一度スキャンし、**ラベル文字列の位置を特定してから値を取り**ます。
項目が別のセルへ移動しても、ラベルの言い回しが違っても読み取れます。

| ゆれ | 吸収方法 |
|---|---|
| 項目位置のズレ（レイアウト3種） | ラベル探索＋右→下の順で値を走査 |
| ラベル文言違い（見積番号 / No. / 見積No） | 候補リストを優先順で照合 |
| 全角数字・カンマ・「円」付き金額 | NFKC正規化 → 数字以外を除去 |
| 日付形式（`2026/01/15` `２０２６－０１－１５` `2026年01月15日`） | 正規表現で3形式を吸収 |
| 会社名（株式会社 / (株) / ㈱ / 「御中」付き） | 正規化して名寄せ |
| 明細行数がファイルごとに違う | ヘッダ行を検出し空行2連続まで読む |
| 宛先ラベルが無く「○○ 御中」だけ | 語尾一致で検出 |

### 実装上のハマりどころ

明細の列見出しが `小計` になっているフォーマットがあり、
素直にラベル検索すると**集計行の「小計」ではなく列見出しをつかみます**。
本ツールは明細ブロックの範囲を先に確定し、集計項目は**明細より下の行だけ**を探索します。

---

## 数字を信じないための検算

抽出して終わりではなく、内部矛盾を検出して `要確認` に落とします。

- 明細金額の合計 ≠ 小計
- 小計 + 消費税 ≠ 合計
- 消費税行が存在しない（税込表記の可能性）
- 必須項目（見積番号・発行日・取引先・合計）が取れなかった

該当行は出力Excel上で**黄色く塗られ**、専用の「要確認」シートにも一覧化されます。
1件読み込みに失敗しても処理は止まらず、その旨を記録して次へ進みます。

## 実行結果（サンプル24ファイル）

```
処理ファイル数        : 24 件
項目の抽出成功率      : 100.0%  (144/144 項目)
警告なしで通った件数  : 20 / 24 件
抽出した明細行        : 77 行
合計金額              : 10,136,100 円
処理時間              : 0.42 秒
```

残った4件はいずれも「消費税行なし（税込とみなす）」で、**意図的に混ぜたパターンの正しい検出**です。
金額の検算はすべて一致しています。

手作業なら1ファイル2分として約50分、しかも転記ミスの可能性が残る作業が、**0.4秒**になります。

## 使い方

```bash
pip install openpyxl
python make_demo_data.py    # input/ にサンプル見積書24件を生成
python aggregate.py         # → 見積一覧.xlsx
```

## 出力（見積一覧.xlsx）

| シート | 内容 |
|---|---|
| 一覧 | 1行1見積。要確認のある行は黄色 |
| 明細 | 1行1明細（品名・数量・単価・金額） |
| 取引先別 | 件数・合計・平均単価（金額降順） |
| 月別 | 年月ごとの件数・合計 |
| 要確認 | 警告が出たファイルと理由 |

## 応用できる領域

抽出したいラベルを差し替えるだけで、同じ仕組みが他の帳票にも使えます。

- 請求書・発注書・納品書の一覧化
- 申込書・アンケート用紙の集計
- 各支店から集まる報告書の統合
- 取引先ごとに書式が違う仕入データの取り込み
